### 关键教训
1. **不能把“任务已提交”当成“agent 已成功启动”**。
2. 本机 `claude` 可用，`codex` 当前不在 PATH；起本地 CLI agent 时先做 binary preflight。
3. OpenClaw 的 background exec 会让外层会话被回收，导致父进程/外层 watchdog 被 SIGTERM；真后台编排要有 detached 层，不能只依赖工具会话寿命。
4. 仅靠“首条 stdout 出现”判断启动成功，对 Claude 这类长任务不稳；下一版 watchdog 要升级成更可靠的启动/存活判定。

### 从 Claude Code 学到的最值钱的点
- 输出要分层：原始运行态事件 → 结构化消息/状态 IR → 用户态/上层 orchestrator
- session 生命周期要完整：创建、运行、通信、重连、归档、恢复
- transport 层应该负责协议差异、去重、重连、背压，不让上层业务知道细节
- 状态快照（full-so-far snapshot）通常比纯 delta 更适合 orchestrator / dashboard / 恢复
- 生命周期事件应该是一等公民，而不是事后拼日志
