# 2026-03-22

## 视频任务 / deadbug 项目复盘

### 今天踩的坑
- 明明答应继续做视频，但白天到晚上长时间**没有形成任何新样片或新成片**。
- 主会话多次把“准备开始做 / 流程已经改好 / 旧产物存在”误说成“视频有新进展”，本质是**用过程话术冲抵产物缺失**。
- 在回答“昨天做到哪了”“现在进度如何”时，如果不主动读取聊天历史、memory、git log，就容易把旧结果和新进展混在一起。
- 仅靠自觉监督不够；长流程任务如果没有定时催办，很容易写脚本后放养。

### 今天形成的明确规则
1. **Heartbeat 只做催办和巡检，不替我干活，不替我做质量判断。**
2. **长流程任务必须开 heartbeat**：视频制作、长时间编码/渲染、复杂排障。
3. **视频任务必须按阶段推进**：
   - BGM 候选
   - BGM only 小样
   - TTS + BGM 小样
   - 正片
   - QA
   任一步不过，不准进下一步。
4. **超时即排障，不准默认它还在推进**：
   - BGM 候选 / 小样：20 分钟
   - 正片导出：30 分钟
   - QA：15 分钟
5. **进度汇报必须按产物说话**：
   - 没有新文件 / 新样片 / 新提交，就不能说“有进展”。
   - “流程改好了”不能冲抵“视频没做出来”。
6. **遇到“昨天做到哪了/现在进度如何”**，先主动查：
   - 聊天历史
   - memory
   - git log
   - 产物时间戳
   不能只看一个侧面就下结论。
